# My Wishlist — React + TypeScript

Готовый адаптивный вишлист: 30 подарков из старого сайта, пять категорий, поиск, сортировка, карточки с оригинальными изображениями и ссылками, совместное/одиночное бронирование, отмена своей брони.

## 1. Запуск на компьютере

Нужен Node.js 20+.

```bash
npm install
npm run dev
```

Открой ссылку из терминала (обычно http://localhost:5173).

Без Supabase сайт запускается в **демо-режиме**: подарки видны, кнопки открывают карточки, но запись бронирования отключена.

## 2. Бесплатный Supabase

1. Открой https://supabase.com/dashboard и создай проект.
2. В **Authentication → Providers → Anonymous Sign-Ins** включи анонимные входы. Это не вход через Google — посетители автоматически получают анонимную учётную запись браузера.
3. Открой **SQL Editor**, вставь содержимое `supabase/setup.sql`, нажми **Run**.
4. В **Project Settings → API Keys** скопируй **publishable key** (допускается legacy `anon` key). В **Project Settings → Data API / API Settings** возьми **Project URL**.
5. Скопируй `.env.example` в `.env` и вставь URL и publishable key:

```env
VITE_SUPABASE_URL=https://example.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxxxxx
```

6. Перезапусти `npm run dev`.

**Никогда не вставляй** service_role key, secret key или пароль базы данных в `.env` для Vite: они попадут в публичный JavaScript.

### Как устроены бронирования

- Все гости видят ники участников. Перед вводом Telegram пользователь об этом предупреждён.
- Одна анонимная учётная запись может занять конкретный подарок один раз.
- Для обычного подарка база атомарно не разрешит вторую бронь.
- Для совместного подарка допускается несколько участников.
- Отменить можно **только собственную** бронь в том же браузере, пока сохранена анонимная сессия.
- Данные синхронизируются при открытии/возврате на вкладку и примерно каждые 15 секунд.
- Анонимный доступ не защищает от намеренного спама с разных браузеров. При публичной раскрутке лучше добавить CAPTCHA/Turnstile и лимиты на стороне сервера.
- Telegram указывается со слов человека и не подтверждает владение указанным аккаунтом.

## 3. GitHub Pages

1. Создай репозиторий на GitHub, загрузи содержимое этой папки (не `node_modules`, не `.env`).
2. В репозитории открой **Settings → Secrets and variables → Actions → Variables**. Создай переменные:
   - `VITE_SUPABASE_URL` — Project URL.
   - `VITE_SUPABASE_PUBLISHABLE_KEY` — publishable/anon key.
3. В **Settings → Pages → Build and deployment → Source** выбери **GitHub Actions**.
4. Запушь код в ветку `main`. Workflow `.github/workflows/deploy.yml` соберёт сайт и опубликует его.
5. Адрес будет вида `https://USERNAME.github.io/REPO/`.

Publishable key не является секретом. Защиту записей обеспечивает **RLS** в Supabase; правила уже заданы в SQL.

Для пользовательского домена или репозитория `USERNAME.github.io` поменяй `BASE_PATH` в workflow на `/`.

## 4. Где менять подарки

- **`src/items.json`** — товары, цены, описания, фотографии, категории и `multi` (можно ли дарить вместе).
- **`src/App.tsx`** — интерфейс и тексты.
- **`src/styles.css`** — оформление и адаптивность.
- Если добавляешь новые ID или меняешь `multi`, поправь каталог в `supabase/setup.sql` и заново выполни его в SQL Editor.

**Важно:** Старые брони Firebase автоматически не импортируются в Supabase. Если они нужны, нужна отдельная миграция. В этой сборке проект начинает с чистого списка бронирований.

Изображения загружаются с внешнего allwebs.ru и могут исчезнуть, если там удалят файлы. Для долгосрочной работы лучше скопировать изображения в `public/images` и заменить ссылки.
